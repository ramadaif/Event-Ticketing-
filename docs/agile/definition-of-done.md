Definition of Done (DoD) : 
Project: Event Ticketing Platform
Model: Agile (Scrum)
The Definition of Done (DoD) represents the set of conditions that must be satisfied for any user story or task to be considered fully completed and accepted within a sprint. This ensures consistency, quality, and alignment with project requirements across all sprints.
________________________________________
DoD Checklist
A user story is considered “Done” only if all the following conditions are met:
1.	All Acceptance Criteria Met
The user story satisfies all defined acceptance criteria clearly and completely without ambiguity. 
2.	Code is Fully Implemented and Functional
The feature is implemented and works correctly without errors or crashes in the application. 
3.	Code is Reviewed
The code has been reviewed by at least one team member and approved (peer review process applied). 
4.	Unit Testing Completed
Unit tests are written and executed successfully, covering the main functionality of the feature. 
5.	No Critical Bugs
There are no critical or major defects remaining. Minor issues (if any) are documented. 
6.	Integrated with Main System
The feature is properly integrated into the main system without breaking existing functionality. 
7.	UI/UX Verified
The user interface is consistent, user-friendly, and follows the agreed UI standards (based on Sprint retrospective improvements). 
8.	Build & CI Passed
The project builds successfully, and the CI pipeline (GitHub Actions) runs without failures. 
9.	Documentation Updated
Relevant documentation (e.g., comments, API description, or README) is updated if needed. 
10.	Product Owner Approval
The feature is demonstrated during the sprint review and accepted by the Product Owner. 
________________________________________
DoD Usage in Sprints
•	The DoD is applied to all user stories in every sprint (e.g., Sprint 1 stories like registration, login, browsing events). 
•	No story is marked as “Done” in the sprint backlog unless it satisfies all DoD conditions. 
•	The team uses the DoD during sprint reviews to validate completed work before acceptance. 
•	Improvements identified in retrospectives (e.g., increasing test coverage or adding UI checklist) are incorporated into the DoD in future sprints.
