Sprint 1 — Retrospective

What Went Well
•	Clear task assignments prevented overlap — each member knew their responsibilities from day one.
•	Early database schema design by Khaled allowed the frontend team to start parallel development with mock data.
•	Daily 15-minute stand-ups kept everyone aligned and blockers were resolved quickly.
•	Git feature branching worked smoothly; no major merge conflicts occurred.
What Could Be Improved
•	Unit test coverage was lower than expected — tests were written last-minute before sprint end.
•	The UI review process was informal; no structured peer review checklist was used.
•	Some acceptance criteria were slightly ambiguous (e.g., 'confirmation message' format not specified).
